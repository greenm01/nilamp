YSFX VS NILAMP PERFORMANCE COMPARISON
=====================================

Updated: 2026-05-12
Platform: macOS 26.4.1, Mac mini Mac16,11, Apple M4 Pro, 12 cores, 24 GB RAM
nilamp commit: ca97506, "Make CLAP and VST3 strictly mono"
REAPER: v7.71


SUMMARY
-------

This note replaces the older mixed Linux/macOS comparison. All numbers below
were recorded on the same Mac after the strict-mono CLAP/VST3 fix was deployed.

Two benchmarks are reported because they answer different questions:

1. `make native-perf-bench` measures audio processing only. It compares
   Keller's TWD DLX II JSFX running under the command-line ysfx harness against
   nilamp loaded as CLAP and VST3. It excludes REAPER, plugin editors, REAPER
   routing, host meters, transport, graphics, and UI event processing.

2. `tools/reaper_perf/measure_reaper_perf_meter.py` samples REAPER's visible
   Performance Meter `CPU` and `FX CPU` values while a ReaScript enables one
   amp format at a time on the same guitar track. This is the best answer for
   "what does REAPER show?" on this Mac.

Headline result:

    Audio-only command-line processing:
        nilamp CLAP:  148.26 ns/frame, 7.06x faster than Keller/ysfx
        nilamp VST3:  148.41 ns/frame, 7.05x faster than Keller/ysfx
        Keller/ysfx: 993.30 ns/frame

    REAPER Performance Meter, editor closed:
        Keller JSFX: 0.825% median FX CPU
        nilamp CLAP: 0.280% median FX CPU
        nilamp VST3: 0.270% median FX CPU

    REAPER Performance Meter, editor open:
        Keller JSFX: 0.880% median FX CPU
        nilamp CLAP: 0.280% median FX CPU
        nilamp VST3: 0.240% median FX CPU

After the strict-mono fix, CLAP and VST3 are tied in the isolated benchmark and
close in REAPER. VST3 no longer shows the previous doubled process cost.


WHY THE VST3 RESULT CHANGED
---------------------------

Before commit `ca97506`, REAPER could call nilamp VST3 with stereo input and
stereo output bus arrangements on a default stereo track. The VST3 accepted
that arrangement and ran two independent mono engines over two host buffers
that carried the same mono guitar content. CLAP advertised mono by default, so
REAPER routed CLAP as mono and avoided the duplicate work.

Keller's TWD DLX II JSFX is strictly mono in / mono out:

    in_pin:mono input
    out_pin:mono output

The current CLAP and VST3 builds now match that contract. VST3 rejects
stereo/stereo bus arrangements and lets the host adapt mono output to the
track. CLAP advertises one mono input and one mono output port, with no stereo
audio-port-config alternative.

NOTES ON DRY AUDIO DURING RUNS
------------------------------

The scenario driver is not intended to measure a dry-guitar scenario. It stops
transport, closes/open FX windows, flips enabled states, restarts playback, and
then waits through the configured settle period before writing the `start`
marker. Any short dry or half-switched audio heard during those transitions is
outside the measured window.

If dry guitar is audible throughout a full 15-second measured segment, that run
should be discarded because the FX chain state is wrong. The `20260512-192716`
run markers show that all three expected FX were found and selected.


LIFECYCLE AND RELOAD
--------------------

The command-line benchmark also reports warm-path lifecycle/reload timings:

    Phase             Surface        Median wall time
    ----------------  -------------  ----------------
    plugin_lifecycle  Keller/ysfx             8.24 ms
    plugin_lifecycle  nilamp CLAP             0.026 ms
    plugin_lifecycle  nilamp VST3             0.006 ms
    reload            Keller/ysfx             8.22 ms
    reload            nilamp CLAP             0.026 ms
    reload            nilamp VST3             0.006 ms

Keller/ysfx lifecycle and reload include JSFX load/compile/JIT behavior. The
VST3 lifecycle/reload numbers are warm-path measurements inside one process, so
they are useful for regression checks but not for cold-start DAW claims.


CONCLUSION
----------

On this Mac, the current strict-mono nilamp build is faster than Keller's TWD
DLX II JSFX in both measured contexts:

    Audio-only command-line benchmark:
        nilamp CLAP and VST3 are both about 7.05x faster than Keller/ysfx.

    REAPER Performance Meter benchmark:
        nilamp CLAP and VST3 both show about 0.24-0.28% median FX CPU, while
        Keller JSFX shows about 0.83-0.88%.

The previous VST3 penalty was a routing contract bug, not a DSP difference.
After forcing both plugin formats to the same mono in / mono out contract as
Keller's JSFX, CLAP and VST3 are effectively tied in the isolated benchmark and
both comfortably below Keller JSFX in REAPER.
